Introduction to Robotics and Control 笔记

2026年7月10日
|

这门 mini-course 的主线不是“如何调用某个机器人软件包”，而是理解机器人系统为什么要这样设计。课堂主要关心以下几个方面的问题：

  • 机器人如何运动：轮子、关节、执行器怎样产生位姿变化。
  • 机器人如何感知：传感器把内部状态和外部环境转成可计算的数据。
  • 机器人如何控制：目标值、反馈误差和控制器怎样闭合成一个系统。
  • 机器人如何导航：仅靠自身运动估计会漂移，必须结合外部观测修正。

1.Robot 的分类

机器人可以按环境和机构、或应用分类。固定式工业机器人常见于汽车、电子制造等生产线，优势是精度高、节拍稳定；缺点是柔性不足，换任务往往要重新配置或编程。移动机器人面对的环境更开放，问题也更复杂：它不仅要执行动作，还要知道自己在哪里、前方是否有障碍、下一步该怎么走。

2. 差速驱动：最基本的移动机器人模型

差速驱动机器人有两个独立驱动轮。左右轮速度相同，机器人沿当前 heading 直行；左右轮速度不同，机器人转弯；左右轮反向转动，机器人可以近似原地旋转。但不能直接横向平移。

也就是说，左右轮速度并不是直接给出 x,yx,yx,y 的变化，而是先决定机器人自身的前进速度和转向速度，再由当前 heading 投影到全局坐标系。

硬件架构与嵌入式系统

一个移动机器人至少包含执行器、传感器、控制器和计算单元。电机提供运动能力，控制器(motion controller)负责底层速度或位置控制，传感器提供状态信息，计算单元(embedded computer) 负责把这些模块组织成一个实时系统。

嵌入式程序通常不是从头到尾顺序执行一次，而是在主循环中持续读取状态、计算控制量、发送命令。遇到安全相关事件时，系统不能等主循环慢慢轮询到它，而要通过 interrupt 立即处理。例如前方突然出现障碍，传感器触发中断，主程序暂停，先执行避障或停车逻辑。

机制典型场景特点
Software interrupt by polling周期性检查水位、电机温度、普通传感器读数实现简单，但响应速度取决于检查频率
Hardware interrupt安全门打开、急停按钮、碰撞触发响应快，适合高优先级事件,比如急停、碰撞
Software interrupt用户改变运行模式或参数用软件事件打断原流程，切换到新的处理逻辑

LiDAR 的价值不只是“测一个距离”，而是通过旋转或多束激光形成二维或三维环境轮廓，为 mapping 和 navigation 提供结构化数据。

Triangulating sensors 的核心是用几何关系反推出距离。光源发出的光照到物体后反射回 detector：若表面光滑，主要发生 specular reflection，入射角等于反射角；若表面粗糙，则发生 diffuse reflection，光会向多个方向散射。实际测距时，系统通常固定光源、detector 和基线长度，通过成像位置变化求目标距离。

若两个三角形相似，关系可写成：

较远目标较近目标
sd=ld′\frac{s}{d}=\frac{l}{d'}ds​=d′l​

其中 lll 和 ddd 为传感器结构中的固定长度，d′d'd′ 可由 detector 上的光斑位置测得，因此目标距离为：

s=ldd′s=\frac{ld}{d'}s=d′ld​

这种方法精度较高，适合多种材料和表面；但它要求光路对准准确，也会受到环境光、反射性质和计算量的影响。

3.2 Camera

Camera 通过 CMOS 或 CCD sensor 把光信号转换成电信号，得到包含颜色、纹理、边缘和形状的图像数据。和单点距离传感器相比，camera 给出的不是一个距离值，而是一整幅 scene，因此更适合 object recognition、tracking、classification 和 scene understanding。

它的优势是信息量大，可以直接服务于 AI perception，例如识别行人、车道线、障碍物或目标物体。课堂里提到不同自动驾驶方案对 camera 和 LiDAR 的选择不同，本质上是在成本、算力、精度和鲁棒性之间取舍。

Camera 的局限也很明确：图像处理计算量大，实时性依赖硬件算力和算法效率；光照变化、阴影、遮挡、反光和低能见度都会影响结果。因此 camera 常和 LiDAR、radar、IMU 等传感器结合使用，用 richer visual information 弥补单一距离传感器的信息不足。

Accelerometer 的基本模型来自牛顿第二定律和弹簧位移。若质量块位移为 xxx，弹簧常数为 kkk，质量为 mmm：

ma−kx=0⇒a=kmxma-kx=0 \quad\Rightarrow\quad a=\frac{k}{m}xma−kx=0⇒a=mk​x

微观实现上，MEMS accelerometer 在芯片内部放置一个可微小位移的 proof mass。加速度使质量块相对外壳发生位移，位移会改变两侧电容 C1C_1C1​ 和 C2C_2C2​。电路读取电容差，就能反推出质量块位移，再换算为 acceleration。

Gyroscope 的核心是 Coriolis effect。若振动质量块质量为 mmm、速度为 vvv，旋转角速度为 ω\omegaω，则 Coriolis force 的大小为：

Fc=2mvω⇒ω=Fc2mvF_c=2mv\omega \quad\Rightarrow\quad \omega=\frac{F_c}{2mv}Fc​=2mvω⇒ω=2mvFc​​

微观实现上，MEMS gyroscope 让内部质量块做等幅反向振动，以抵消 common-mode noise。当传感器发生旋转时，Coriolis effect 会让振动质量块在 sensing direction 上产生侧向 deflection。这个 deflection 通常也通过电容变化检测，并被转换成与 angular velocity 对应的电压信号。

4. Odometry

运动学从最基本的距离、速度、加速度开始：

v(t)=ds(t)dt,a(t)=dv(t)dtv(t)=\frac{ds(t)}{dt},\qquad a(t)=\frac{dv(t)}{dt}v(t)=dtds(t)​,a(t)=dtdv(t)​

若加速度为常数，且初始速度和位移取 0，则：

v(t)=at,s(t)=12at2v(t)=at,\qquad s(t)=\frac{1}{2}at^2v(t)=at,s(t)=21​at2

更真实的运动还要考虑阻力。比如“恒定功率汽车”说明速度不会无限增加：设车辆质量为 mmm，发动机功率为 PPP，滚动摩擦为 F1F_1F1​，空气阻力为 F2F_2F2​，则

F1=μmg,F2=12ρCdAv2F_1=\mu mg,\qquad F_2=\frac{1}{2}\rho C_dAv^2F1​=μmg,F2​=21​ρCd​Av2

其中 AAA 是迎风面积，CdC_dCd​ 是 drag coefficient(阻力系数)，μ\muμ 是滚动阻力系数，ρ\rhoρ 是空气密度。功率 PPP 对应的牵引力为：

Ft=PvF_t=\frac{P}{v}Ft​=vP​

总阻力为：

Fr=F1+F2=μmg+12ρCdAv2F_r=F_1+F_2=\mu mg+\frac{1}{2}\rho C_dAv^2Fr​=F1​+F2​=μmg+21​ρCd​Av2

由牛顿第二定律：

Ft−Fr=mdvdtF_t-F_r=m\frac{dv}{dt}Ft​−Fr​=mdtdv​

得到速度随时间变化的方程：

dvdt=1m(Pv−μmg−ρCdAv22)\frac{dv}{dt} = \frac{1}{m} \left( \frac{P}{v} -\mu mg -\frac{\rho C_dAv^2}{2} \right)dtdv​=m1​(vP​−μmg−2ρCd​Av2​)

这是 nonlinear first-order ODE，通常用数值方法求解。直觉上，低速时牵引力较大，速度上升较快；速度升高后空气阻力按 v2v^2v2 增大，最终牵引力只够抵消阻力，车辆达到 terminal velocity。室内移动机器人速度低、距离短，一般不会真正达到这个极限状态。

Odometry 是利用 proprioceptive sensors 随时间积分来估计机器人位置和朝向的过程。移动机器人中的 pose 通常写成：

p=(x,y,θ)\mathbf{p}=(x,y,\theta)p=(x,y,θ)

其中 (x,y)(x,y)(x,y) 是位置，θ\thetaθ 是 heading。

4.1 Linear odometry

如果机器人在短时间内沿当前 heading θ\thetaθ 以速度 vvv 运动 Δt\Delta tΔt，则位姿变化近似为：

Δx=vΔtcos⁡θ,Δy=vΔtsin⁡θ,Δθ=ωΔt.\begin{aligned} \Delta x &= v\Delta t\cos\theta,\\ \Delta y &= v\Delta t\sin\theta,\\ \Delta \theta &= \omega\Delta t. \end{aligned}ΔxΔyΔθ​=vΔtcosθ,=vΔtsinθ,=ωΔt.​

连续时间下：

x(t)=x(0)+∫0tv(τ)cos⁡θ(τ) dτx(t)=x(0)+\int_0^t v(\tau)\cos\theta(\tau)\,d\taux(t)=x(0)+∫0t​v(τ)cosθ(τ)dτ y(t)=y(0)+∫0tv(τ)sin⁡θ(τ) dτy(t)=y(0)+\int_0^t v(\tau)\sin\theta(\tau)\,d\tauy(t)=y(0)+∫0t​v(τ)sinθ(τ)dτ

这是 dead reckoning(航位推测) 的核心：从已知初始位姿出发，根据每一步运动估计当前位置。

4.2 Rotational Odometry

转弯时左右轮走过的距离不同，机器人中心沿圆弧运动，heading 也随之改变。设在时间 Δt\Delta tΔt 内左右轮走过的弧长为 dl,drd_l,d_rdl​,dr​，若课件中轮速单位为 rotations/sec，则：

dl=2πRωlΔt,dr=2πRωrΔtd_l=2\pi R\omega_l\Delta t,\qquad d_r=2\pi R\omega_r\Delta tdl​=2πRωl​Δt,dr​=2πRωr​Δt

dc=dl+dr2=πRΔt(ωl+ωr)d_c=\frac{d_l+d_r}{2} =\pi R\Delta t(\omega_l+\omega_r)dc​=2dl​+dr​​=πRΔt(ωl​+ωr​)

左右轮弧长差决定转角。因为两轮轨迹半径相差 bbb，有：

ϕ=Δθ=dr−dlb=2πRΔtb(ωr−ωl)\phi=\Delta\theta =\frac{d_r-d_l}{b} =\frac{2\pi R\Delta t}{b}(\omega_r-\omega_l)ϕ=Δθ=bdr​−dl​​=b2πRΔt​(ωr​−ωl​)

θ′=θ+ϕ\theta'=\theta+\phiθ′=θ+ϕ

x′≈x+dccos⁡θ,y′≈y+dcsin⁡θx'\approx x+d_c\cos\theta,\qquad y'\approx y+d_c\sin\thetax′≈x+dc​cosθ,y′≈y+dc​sinθ

4.3. Odometry error

Odometry 的问题是误差会积累。轮子slip or skid、地面不平、传感器噪声、安装误差和数值积分都会让估计位姿偏离真实位姿。尤其是 heading error，常常比单纯的距离误差更危险，因为一个小角度误差会随着行驶距离放大成横向偏移。

假设机器人沿 xxx 方向行驶距离 sss，距离误差和 heading 误差都不超过 p%p\%p%。线性误差可写成：

Δx≤0.01sp\Delta x \le 0.01spΔx≤0.01sp

若 heading error 按 360∘360^\circ360∘ 的 p%p\%p% 估计：

ϕ=2πp100=0.0628p rad\phi = 2\pi\frac{p}{100}=0.0628p\ \mathrm{rad}ϕ=2π100p​=0.0628p rad

横向偏差为：

Δy=ssin⁡(0.0628p)≈0.0628sp\Delta y=s\sin(0.0628p)\approx 0.0628spΔy=ssin(0.0628p)≈0.0628sp

因此：

差速机器人是理解 under-actuated 的好例子。它在平面中的 pose 是 (x,y,θ)(x,y,\theta)(x,y,θ)，但只有左右两个独立轮速输入，因此不能直接横向移动。要到达侧方位置，它必须先转向、前进或后退，再调整 heading。汽车倒车入库难，本质上也和这种运动约束有关。

redundant系统则相反。它拥有比任务所需更多的执行能力，所以同一个目标 pose 可能有多种 configuration。好处是可以避障、优化能耗、改善受力分布、提高 fault tolerance；代价是控制和规划问题更复杂。

Robotic crane 是 redundant system 的一个例子。被吊起的 weight 只做竖直方向运动，任务本身是 1 DOF；但系统使用两个 actuator：右侧 driven wheel 通过 road wheels 带动整个平台前后移动，使 weight 可以快速产生 coarse motion；左侧 driven wheel 带动 winch 收放 cable，使 weight 可以更慢但更精细地 vertical motion。也就是说，两个 actuator 共同服务于一个竖直运动任务，用 redundancy 换来 rapid movement 和 fine motion 的组合。

6.2 Behavioral Control

PID 的任务是让 robot follow a given trajectory。假设原来规划的是 p₀，robot 可以靠 PID 尽量贴着 p₀ 走；但如果 p₀ 上突然出现 obstacle，PID 不会自己决定改走 p₁ 还是 p₂。

这里要加一层 behavioral control：

  1. Behavior controller 根据传感器信息决定继续、转向或重新规划，给出新的 path；
  2. PID 再负责沿新的 path 行驶。
